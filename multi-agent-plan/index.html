多agent评测的两条主线

文献查完，三十篇里能画成图的数都抠了一遍，「按任务选机制的调度层」这句话已经有八家在做，不能再当贡献。还剩下的位置有两个，一个在运行中，一个在开跑前，合起来才是调度层。每条给机制示意、预期结果和空位证据。

0一句话

多agent什么时候赚、赚在哪，文献已经答了一半：收益来自验证过的进展共享，前提是中途能验证。没人做的是把这件事变成可调的东西：运行中按验证结果把输家的算力拨给领先者，开跑前按便宜信号选三类机制并报扣掉探测成本的净值。两条线共用同一批case和同一个grader。

  1. 01主线一，运行中拨算力。K个会话并行，共享一张带复现证据的榜，到检查点淘汰后一半，把它们剩下的预算给前一半，从领先者的状态fork出变体。总token拉平。目标是第一个在总量拉平下多agent赢的编码结果。
  2. 02主线二，先看有没有万能做法，没有再提前猜，猜值不值。先量每道题最好的做法是不是不一样，不一样再用一分钟探测去猜该用哪种，最后算猜对多赚的分减去猜花的钱。最后这一减没人报过。
  3. 03前置实验，验证粒度当自变量。同一个任务给不同密度的中途验证器，看team@k减best@k随粒度m怎么变。Park的理论预言它从负穿到正，没人扫过。这张图直接回答「什么任务该上多agent」。

1主线一：运行中按验证结果拨算力

Liu等（2609.15309，Chai在作者里）测出1亿token给一个会话不如切成3份，切10份又不如3份，拐点是边际Elo掉到独立采样参考线以下。但它的切法事先定死，中途不调。Park（2609.21032）的团队靠一张带复现证据的榜共享进展，可它控的是每人额度，总量拉平那一组反而输给单agent。ATM、TacoMAS、DyLAN三家做运行中改结构，全是只砍不并。把这三件事接起来就是主线一。

空位证据我们补什么
切法事先定死Liu 2609.15309：K从单会话曲线预测，中途不调检查点上按榜动态调
只砍不并ATM 2607.20488拆过载agent；TacoMAS 2605.09539删agent；DyLAN 2310.02170停用agent，三家都不回收算力淘汰者的预算转给领先者
总量拉平时团队输Park图4：五人每人0.2倍，过第1关和第3关后归零K随预算自适应，小预算退化成单会话
委派是加活DeLM 2606.10662：Claude Code和Codex的原生subagent四格没赢过单harness不委派，fork的是完整状态

做法上最省的路径：用现有的Claude Code adapter，K个会话各开一个worktree，榜是工作区里一个只追加的文件，检查点由runner按token计量触发。grader已经有互相覆盖、并发写这些指标，加一列「fork谱系」就够。

2前置实验：验证粒度当自变量

主线一要能中途打分。能不能中途打分，本身就是文献里最该量而没人量的变量。Park的形式化是T_team = Σ_j min_i X_ij ≤ min_i Σ_j X_ij = T_best，前提是任务能切成m段可验证的进展。它在ARC-AGI-3上m是关卡数，team@5比best@5高5.8个点；在Terminal-Bench 2.0上验证器跑完才给反馈，m≈1，team@2比pass@2低1.7个点。两个点都是它自己的数，中间没人扫过。

这张图比任何路由器都好讲：横轴是任务的一个可测属性，纵轴直接是该不该上多agent。它也是主线二的输入，「有没有中途验证器」是路由信号之一。

3主线二：每道题都该用同一种做法吗？不是的话能不能提前猜，猜值不值

多agent有好几种组织方式，这页叫三类：切分（拆开各做一块）、独立（各做全部挑最好）、共享（各做全部，发现写进共享榜）。每类里还有四个档位可调（拓扑、记忆共享、权限、调度），先只看三类。主线二问的是：是不是每道题都该用同一种？不是的话，能不能开跑前就猜出该用哪种？猜这件事值不值？

三个术语先翻成人话。翻转：没有万能的做法，同一种做法这道题最好、那道题最差。路由：开跑前选做法，用一分钟探测到的几个数去猜。净值：猜对多赚的分，减去猜本身花的钱。三步正好对应三个词，前一步不成立后一步不做。

第一步，量翻转：我们的题里有没有「没有万能做法」这回事

把每道case在三种方式下各跑一遍，得到一张「每道题每种做法得几分」的表。用两道已有的case举例，数字是示意：

case切分独立共享这道case的最优
broad-lookup（20家公司各查CEO，子任务互不依赖）0.900.600.70切分，0.90
coupled-game（三个文件接口互相依赖）0.300.600.65共享，0.65
两道平均0.600.600.675逐case取最优的平均，0.775

四个定义，全从这张表里读：

  • 翻转：两道case的最优方式不同（切分对共享）。这两道正好是P-09里的一对，A侧该让并行切分帮忙，B侧该让它拖后腿。
  • oracle：事后知道每道case哪种最好，逐case取最优再平均，0.775。它是任何选法的上限。
  • 固定最优：全部case只准用一种方式，挑平均最高的，共享0.675。它是不选的下限。
  • oracle余量：两者之差，0.10。这是「会选」最多能多赚的分。余量不超过噪声地板，第二、三步不做，报「调度层没东西可调」。

现有文献的洞就在这一步：Harness-Bench有一致赢家但没报任务级翻转，八家路由器全都默认翻转存在，没人量过余量。我们有3对6道成对对抗case，10.23前到至少3对进正式评测，翻转矩阵就是这张表扩到几十行。

第二步，路由：开跑前猜该用哪种

不能等跑完才知道，那时钱已经花了。所以先让一个agent跑一分钟，读四个数去猜。这四个数不是拍的，每个对应一条文献里被证明会翻结论的变量：

信号读什么它预示什么依据
工具调用熵第一分钟调了多少种工具、分布多散工具多，切分型吃亏，中间转述丢工具状态Kim：工具交互系数−0.096，p=0.002
并行宽度任务能同时推进的独立线有几条宽，切分赚；窄成链，切分亏Kim：Finance +80.8对PlanCraft −70；Chai的DAG宽度
有无中途验证器能不能在做完之前给子结果打分有，共享赚；没有，共享传的是噪声Park：ARC +5.8对Terminal-Bench −1.7
进展斜率单agent第一分钟分数涨多快慢，说明一个人用不好上下文，切分或共享才有空间；快，单agent够用Kim：单agent过45%就别加人；TAMU：强模型切分亏

猜的规则不是人定的，是一棵决策树从第一步那张表上学出来的：输入四个数，输出三类取一、四个档位各取一。不用RL，Kim用20个参数的回归在未见过的配置上选对87%，我们几十道case，树够用。

第三步，净值：猜对多赚的分，减去猜本身花的钱

用regret衡量，regret就是比oracle少拿的分，越小越好。报三列：

  • 固定最优的regret：0.775−0.675=0.10。不选，就亏这么多。
  • 路由器的regret：路由器每道case选中了最优就是0，选错一道就亏那一道的差。示例里两道都选对，0。
  • 路由器加探测成本的regret：探测那一分钟花的token按同样的分数折算进去，示例里折0.02，第三列0.02。

路由划算，当且仅当第三列小于第一列，也就是扣掉探测的钱还比不猜强。示例里0.02小于0.10，划算。三步跑完结论只有三种：没有翻转，固定用最好的一种；有翻转但猜不准或猜太贵，知道有空间拿不到；有翻转且猜得准又便宜，meta-harness的选择层才成立。COVER在ToolSandbox上第二列就是0.131，没过它自己预注册的0.10，所以这一步有真实的概率是负结果，论文里提前写。

4两层合起来才是调度层

创新点归成五条，每条后面是它对应的空位证据：

  1. 验证粒度m当自变量。Park给了两个端点，中间没人扫。
  2. 总量拉平下的动态并拨。Liu切法定死，三家只砍不并，Park总量拉平那组是负的。
  3. 三类路由，候选含共享型。八家全是切分型。
  4. regret三列，扣探测成本。COVER不算路由开销，Kim要先跑单agent。
  5. 翻转先量再路由，成对对抗case当地基。六家当动机写，没人量；成对设计的祖宗是2306.03034，LLM这边没有。

方法论上另有两条，不算创新但审稿必问：单agent基线用best-of-k不用单次（2605.01566和2502.08788证明换基线结论翻）；先跑2606.20695的噪声地板，两个seed各100题。

5理想中的meta-harness

套在现有harness外面的一层，一道任务从进来到记账走五步：探测、选择、执行、调度、记账。前两步开跑前做一次，后三步每个检查点做一次，最后一步的产出回流给第二步。

五步各自的输入输出，写死：

  1. 探测。输入任务；跑一分钟单agent；输出工具调用熵、并行宽度估计、有无中途验证器、进展斜率。
  2. 选择。输入四个数加模型档；决策树，训练集是评测网格；输出三类取一、四因子各一档，附预测regret。
  3. 执行。原语：会话池K、榜（分数、复现步骤、谱系，sha256重打分）、租约加共享完成态、按角色的上下文与权限作用域、验证器露出层数m、检查点。配置只是在这些原语上取值。
  4. 调度。每个检查点：读榜，算每个会话的边际进展对独立采样参考线，低于线收掉，预算并给高于线，从领先者fork带变体；预算用完或连续两个检查点无改进就停。总token恒等于预算。
  5. 记账。Cost/Task、Cost/Submission、探测成本、六个协调指标、每个决定的日志。写回评测网格。

不变量五条，任何一步都不能破：总token恒等于预算；榜条目可复现；协议由运行时强制，不靠prompt；共享产物写入串行；每个决定留日志，regret可审计。

和现有工作的边界：MaAS到MACA八家做的是选择这一步且候选没有共享型；ATM、TacoMAS、DyLAN做的是调度这一步且只砍不并；DeLM做的是执行层的榜和队列；grite做的是执行层的租约。五步合一、每步有评测产出的数作依据，没人做过。
