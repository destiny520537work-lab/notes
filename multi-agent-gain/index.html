多agent的收益从哪来

三十篇论文的原始数字，按两件事重排：实验怎么控算力，agent之间传什么。控法一换结论就翻；传的东西决定收益来自哪、什么时候没有。玩具模型只留末尾一张。

  1. 01控算力有三种，结论随控法翻。总token拉平，单agent赢；每个agent额度相同，团队顶得上4到7倍的独立agent；把团队总量压到和单agent一样，团队又输。同一篇论文里都有。
  2. 02切分型赚在压掉噪声上下文，共享型赚在验证过的进展。前者弱模型赚强模型亏，18格受控实验测出来的；后者要有中途验证器，没有就传噪声。
  3. 03人多不灵的原因量出来了。30个辩论agent的答案多样性和1个一样；两个agent协作比一个agent做两件事低20个点；团队用不上自己最强的成员。
  4. 04报出来的收益里有一截是钱和噪声。harness方差是模型方差的7.8倍；同一配置换个马甲，配对差就有12到15个点，十条已发表的收益里七条在这条线之下。

1控算力有三种，这个领域把它们混着引

「拉平预算后多agent还行不行」这个问题，文献里至少有三种答法，而且经常被放在一句话里互相引用。先把它们分开。

控法意思谁结论
甲 总量拉平所有agent加起来和单agent花一样多Tran和Kiela，2604.02460；Kim 2512.08296（匹配最大迭代数，均值4800 token）；TAMU 2607.16133（总步数）；Liu 2609.15309（1亿token切K份）多跳问答单agent赢；Kim六个benchmark有赢有输；TAMU弱模型赢强模型输

丙 不拉平，报成本效果和token或美元一起报，画成本对效果哥廷根，2605.01566（Pareto前沿）；DeLM 2606.10662；LATTE；Salesforce 2606.13003；MAS-Orchestra；Harness-Bench看基线。基线是self-consistency时多agent赢1.3到2.7个点，基线是单次CoT时看任务

上面那张图是甲里最干净的一个。乙那一类看下一节Park，丙和丁看第4节。甲和丙的分歧点在基线：Tran和Kiela的单agent是一次调用，哥廷根的基线是self-consistency。换一个基线，等算力下的结论就翻。哥廷根在MMLU-Pro上的数：CoT一次64.3，self-consistency十条68.7，辩论4人2轮70.0，mixture-of-agents 5模型4层71.4，横轴是估算的运行时。按难度拆，容易题只涨2.2个点，难题从8.4涨到17.4。

我们的评测在丙，主图是成本对完成率。论文里要把这一点讲出来，附一张单agent best-of-k的表堵住甲的问题。

2切分型：收益来自压掉噪声上下文，强模型就没了

切分型是把任务拆开、各做一块、文字汇总。Kim那篇用260个配置测了它的四种拓扑，预算按迭代数匹配。六个benchmark的方向各不一样：

Kim给了方向，没给机制。机制是德州农工那篇（2607.16133）用一组三臂对照拆出来的：单agent一份上下文；按多agent的方式拆，但累积上下文全可见；按多agent的方式拆，每个worker只拿压缩过的转述。中间那一臂是关键，它把「拆」和「压」分开了。

所以切分型的判据是单agent的上下文用得好不好，和任务长不长没有直接关系。Liu等（2609.15309）从另一头测到同一件事：把1亿token给一个会话还是切成K份，Elo随K先升后降，拐点在3份，比1份高264 Elo，比10份高355。切得太碎是独立采样，不切是长会话自己退化。

3共享型：收益来自验证过的进展，要有中途验证器

Park那篇（2609.21032）的agent一模一样，没有角色，没有协调者，不拆任务。每个人各有草稿目录，共用一个只追加的日志当异步广播，一张记录「方法、结果、复现步骤、反证」的榜，改共享产物用文件锁。规则是明显更好才采纳，采纳后保留一个自己的变体。对照是best@k：k个不说话的agent里最好的那个，从64次单跑里无放回地精确算出来。

机制一句话：独立采样要一个人把m段改进全走完，团队每一段可以用不同人的突破，T_team = Σ_j min_i X_ij ≤ min_i Σ_j X_ij = T_best。前提是每一段的进展能被验证、能排序。Terminal-Bench 2.0上验证器跑完才给反馈，中间进展排不了序，team@2 60.67%低于pass@2 62.36%，论文自己写的反例。

DeLM（2606.10662，Stanford）把同一思路放到真实编码任务上，没有任务图：共享上下文加任务队列，发现什么立刻公布，压缩成带证据的gist，异步认领。它和Park的差别在对照组：同一个模型、同一个harness，只换协调方式。

4独立型是该用的基线，用错基线结论翻

独立型是N个agent各干各的不交流，最后挑最好的或投票。best@k、pass@k、self-consistency、CoT-SC都是它。它是Park要打败的对手，也是第1节甲和丙分歧的根源。两组数说明为什么它该是基线。

MASLab（2505.16988）的符号翻转是跨模型家族的：AgentVerse对单agent，Llama-3.3-70B上+2.3，Qwen-2.5-72B上−0.9；DyLAN +3.1对−0.6。最好的MAS减单agent的差距从4.7掉到1.7。原话是「没有方法在所有领域称霸」。

5人多了为什么不灵：三个量出来的原因

第一，同质团队的辩论不增加多样性。Jožef Stefan那篇（2606.02646）给了一条标度律：有效人数比R(N)=1/(1+c(N−1)N^−β)，β=0是硬天花板，0到1之间是次线性。44个格拟合，中位R²0.999。

第二，协作本身有成本，而且比想的大。CooperBench（2601.13295，Stanford）652对任务，每对是同一个仓库上的两个feature。Solo一个agent做两个，Coop两个agent各做一个、能互发消息，每人100步，所以Coop的总动作是Solo的两倍。

第三，信息分散时规模越大越差。HiddenBench（2505.11556，ICML 2026）65道隐藏信息题，15个模型：一人拿全部信息80.7%，四人各拿一份再讨论30.1%。GPT-4.1上讨论带来的提升从3人时的+0.348掉到7人时的+0.006。Silo-Bench（2603.01045）把任务按通信复杂度分三级，DeepSeek-V3.1从2人的61.2%掉到100人的18.1%，到了全局洗牌那一级GPT-OSS在50人时归零。

6差距里多少是钱、多少是噪声

上面那些比较，大部分没拉平算力。两组数说明不拉平会差多少。

噪声那一头，UT Austin那篇（2606.20695）做了件很简单的事：拿两个功能完全等价、只是形式不同的协调配置，等价性用代码审查和SHA-256校验过，在同一模型同一benchmark上各跑100题，看配对差。差多少，就是这个benchmark上「什么都没变」能变出多少。

三个坑。一，八家选的全是切分型的图，没有一家把Park那种共享型放进候选。二，训练集几乎全是短任务，MasRouter一道agentic任务都没有，长程上成不成立没人验过。三，Kim那个回归的输入里有单agent基线，等于要先跑一遍单agent才能决定要不要多agent；COVER是唯一量了oracle差距的，而且没过自己的线。路由器自身的开销和为了训它做的探测成本，没有一家扣出来报净值。

我们的14个case标上并行宽度、可验证性、单agent基线，三个harness的成绩表出来，一个决策树就是这颗brain的第一版。Kim用回归就到87%。候选里把共享型加进去，就是上面那个空位。

10对评测的六条

  1. 单agent基线用best-of-k，不用单次。k取到token和多agent差不多。2605.01566和2502.08788都证明单次和self-consistency当基线结论会翻。这是P-13未决里那张附表，建议拍掉。
  2. 先跑噪声地板。照2606.20695：两个功能等价的协调配置，同模型同benchmark各跑一遍，差值就是地板。14个case的规模按它的检出力表，只能检出20个点以上的差。
  3. 14个case标三列：类（切分、独立、共享）、子结果能否独立验证、单agent天花板。第三列现在0/14，用订阅就能跑，不用等API key。
  4. grader加随机剪枝自检：随机砍掉一半agent再跑，成绩不掉的case证明不了协作。2609.05933点名这是通病。
  5. P-13保留，理由写进论文：这项评测答「机制能做到多好」，不答「同样的钱谁更划算」。效果、成本、比例三列一起报，附best-of-k表。
  6. 三条引用口径：LATTE写arXiv不写NeurIPS；Ord的λ不当测量引，要λ引2606.02646；Park的「三倍」要写明是每agent拉平下的等效人数，总量拉平那组是负的。
